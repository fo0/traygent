## New session — „Neue Session“

One composer, no prose:

- **Agent** — **Claude Code · OpenCode · Codex**; each carries a status dot for the selected environment. The selected button shows the time of its last successful quota read at the top right. Hover over the time to see the refresh interval. On the **Woche** row, **3 Tage · 68 % frei** means the weekly quota resets in three days and 68% remains. The bars along the bottom show the share already used. They turn amber at 70% and red at 90%. Hover over a button for details. An unavailable quota has no percentage. An agent whose quota read is off shows neither a percentage nor bars.
- **Kontingent** under **Einstellungen → Agenten** turns the selected agent’s quota read on or off (**Kontingent abfragen**) and controls its bars and their order. The read is off by default for Claude Code and Codex: it reuses the CLI’s subscription sign-in against a provider interface that is not officially documented ([ADR-0014](adr/0014-opt-in-subscription-quota-reads.md)). OpenCode reads with your own OpenCode Go key and is on by default. While the read is off, the bar choices are unavailable. The weekly bar is always enabled. Other available windows depend on the subscription, such as Claude’s session or Fable limit. Compact buttons always show just the week.
- **Folder or repository** („Ordner oder Repo“) — the field starts empty, its placeholder names both forms. Type a folder, browse with the native folder dialog or pick one of the recent folders — or name a GitHub repository: paste its URL, type `owner/name`, or type a few letters to get suggestions from your connected account ([below](#start-from-a-github-repository)). **Ctrl+L** jumps to the field and selects its text. **Escape** clears it (an open suggestion list closes first).
- **Environment** — **Lokal** (local) or **Docker**; **WSL** is shown disabled („Bald verfügbar“, coming soon). Environments you hide under **Einstellungen → Umgebung → Umgebungen** leave the composer; with just one, the row disappears.
- **Option chips** — start from the saved defaults and change the next start only:
  - **Modell** — the model.
  - **Denken** — the effort level; only where the agent has one.
  - **Freigabe** — the permission mode: a symbol that cycles **Nachfragen** (ask) → **Auto** → bypass, its label in the tooltip, the bypass in a warning colour. The bypass label follows each CLI — **Bypass** for Claude Code, **YOLO** for Codex and OpenCode.
  - **Session** — **Neu** (new) / **Fortsetzen** (continue) / **Auswahl** (pick from the agent's session list), where the agent supports them.
  - **Profil** — Lokal and Docker, once the agent has a second profile ([below](#several-accounts--profile)): a round mark — a person for **Standard**, else the profile's initial — that picks which sign-in the next start uses; in a warning colour while that profile is not signed in.
  - **Ports** — Docker only: checkboxes for common dev-server ports (3000 Next.js · Node, 5173 Vite, 4200 Angular, 8000 Django · FastAPI, 8080 Spring, 5000 Flask · ASP.NET, 4321 Astro, 6006 Storybook) plus custom Docker specs such as `8080:80` or `3000-3002/udp` (several at once, separated by spaces or commas). Ports bind to `127.0.0.1` unless an IP is typed explicitly.
- **Starten** (start) or **Enter** opens the session. When the agent's CLI is missing locally, the button reads **Installieren …** and opens **Einstellungen → Agenten** for it — never a dead start. While something blocks the start (no folder yet, an invalid option), a press names the reason below the button until it is fixed.

## Workspaces

- One single-line row per folder, agent and environment, newest first, at most 20.
- Each row shows the agent icon (with the profile's initial on its corner when it started with a profile other than **Standard**), folder name and parent path, then fixed columns at the right edge, so every icon sits in the same column from row to row (an absent part leaves its column empty): a `</>` mark when a restart passes extra arguments (the arguments are in the tooltip), published ports, a repository icon when it was started from GitHub, the environment icon, the options as symbols and a relative time.
- Options as symbols: the chosen model as a one-letter badge (Opus **O**, Sonnet **S**, Haiku **H**; Codex models by their own word: Sol **S**, Astra **A**, Terra **T**, Luna **L**), the thinking level as signal bars, the permission as a symbol.
- A click anywhere on the row (or **▶**) starts that session again with exactly those settings — once per press, so a double-click never starts it twice.
- **Ctrl+1** … **Ctrl+9** start the first nine rows the same way from anywhere in the panel, the folder field included; a held key starts once, and the row's tooltip names its key.
- A row whose profile was removed in the settings shows a **?** on the agent tile (**Profil entfernt**) and does not start — it never falls back to another profile; pick one under **Bearbeiten …**.
- With the keyboard on a row's **▶**, **↑** / **↓** move to the row above or below, **Home** / **End** to the first or last row.
- The **⋯** menu offers **In Composer übernehmen** (copy into the composer), **Bearbeiten …** (edit the model, thinking level, permission, extra arguments, Docker ports, **Docker-Socket durchreichen** and — for an agent with profiles — the **Profil** the row starts with, without starting it; a profile removed meanwhile shows as **Standard**; **Modell & Denken**: **Traygent** sets the stored model and thinking level on every start, **Agent** passes neither so the agent keeps what it last used, e.g. after `/model`), **Ordner öffnen** (open the folder in Explorer), **Pfad kopieren** (copy the folder path) and **Entfernen** (remove) with **Rückgängig** (undo) for 8 seconds.

## Status and refresh

- The footer shows the Docker state (**Docker 27.5 · bereit** = ready, or why it is not; only while Docker is shown) and when detection last ran (**Stand hh:mm** = as of hh:mm).
- Detection runs at startup and on the refresh button, **F5** or **Ctrl+R**, off the UI thread. Refresh also checks the quotas. While the panel is visible, it checks them every 15 minutes by default and after a reported reset. Set the interval from 1 to 60 minutes under **Einstellungen → App**.
- Only agents with **Kontingent abfragen** on are checked. Quotas follow the selected launch account. Claude Code and Codex can use their shared host sign-in in Docker. OpenCode V2 uses its selected Go account for local sessions. Its Docker sign-in lives in a separate volume and the Docker quota is unavailable. File-backed Claude and Codex sign-ins need a valid CLI access token. A tooltip explains when a quota cannot be read. A failed check keeps the last reading for up to 15 minutes, and never past its own reset time.

## Settings — „Einstellungen“

Nothing applies until **Speichern** (save); **Abbrechen** (cancel) drops it. The one exception: adding a profile ([below](#several-accounts--profile)) saves it at once.

- **Agenten** (agents) — per agent the local status (version or why not) and the Docker readiness, the recommended install command with a copy button and **Installieren** (install; opens a terminal running it; refresh detection afterwards), the update command, and the defaults: model, effort, permission and extra CLI arguments (validated). Claude Code also has **Profile** ([below](#several-accounts--profile)).
- **Umgebung** (environment) — the environments the composer shows (**Umgebungen** = environments; recents of a hidden one still restart unchanged), default environment and agent, terminal (Windows Terminal or Konsole = classic console) with **Ein Fenster für alle Sessions** (one window for all sessions; Windows Terminal only, off by default: every session opens as a new tab of one shared window), the Docker image per agent, **GitHub-Token weitergeben** (forward the GitHub token; off by default) and **Docker-Socket durchreichen** (pass the host Docker socket; off by default, [below](#docker-sessions)).
- **GitHub** — the connected account (**login · Token** or **login · gh CLI**) with **Aktualisieren** (refresh) for its repository list and **Trennen** (disconnect, inline confirmation); without one, **Lokale Anmeldung prüfen** (check local sign-in) + **Übernehmen** (adopt) imports a GitHub CLI sign-in, or a personal access token connects with **Verbinden** (connect). Account actions apply at once; the **Klon-Ordner** (clone folder) is staged like every setting.
- **App** — theme (System / Hell = light / Dunkel = dark) and **Mit Windows starten** (start with Windows, [details](WINDOWS_AUTOSTART.md)).
- **Updates** — in-app updates: **Nach Updates suchen** (check for updates), at most 5 changelog bullets, **Installieren** ([release process](RELEASES.md)). Below it **Agenten**: **Automatisch aktualisieren** (off by default) keeps the installed agent CLIs up to date — shortly after the app starts and every 4 hours, each CLI's own update command runs in the background, skipped while that CLI is in use; **Jetzt aktualisieren** runs it at once, and one line per agent shows the last result.

## Panel and tray

The panel opens beside the tray icon; placement follows the clicked icon, monitor work area and DPI. Clicking outside hides the panel while preserving open forms; a start hides it so the new terminal gets the focus. **Traygent beenden** (quit Traygent) in the tray menu exits.

## Supported agents in detail

Traygent maps one permission choice to each agent's own flags and launches the CLI by absolute path. Flags, install paths and the Docker recipes are researched in [AGENT_RECIPES.md](AGENT_RECIPES.md).

| Agent       | Nachfragen / Auto / Bypass · YOLO                                                                                                                                               | Sessions                   | Docker volumes                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | ----------------------------------------------------------------------------- |
| Claude Code | `--permission-mode default` / `--permission-mode auto` (both with `--allow-dangerously-skip-permissions`, so Shift+Tab still reaches bypass) / `--dangerously-skip-permissions` | Neu · Fortsetzen · Auswahl | `claude-code-tools`, host Claude config                                       |
| OpenCode V2 | the user's config rules / `--auto` / `--auto` plus an allow-all rule in `OPENCODE_CONFIG_CONTENT`; always `--standalone`                                                        | Neu · Fortsetzen           | `traygent-opencode-bin`, `traygent-opencode-data`, `traygent-opencode-config` |
| Codex       | `--sandbox read-only --ask-for-approval on-request` / `--approve-for-me` / `--dangerously-bypass-approvals-and-sandbox` (in Docker the sandbox is `danger-full-access`)         | Neu · Fortsetzen · Auswahl | `traygent-codex-tools`, host Codex home                                       |

Model and effort travel as `--model` / `--effort` (Claude), in `OPENCODE_CONFIG_CONTENT` as `provider/model#variant` (OpenCode) and as `-m` / `-c model_reasoning_effort=…` (Codex) — none of them for a workspace set to **Modell & Denken** → **Agent**. Extra arguments follow last, one literal each.

## Start from a GitHub repository

The folder field also takes a repository ([ADR-0005](adr/0005-start-from-a-github-repository.md)):

- **Recognised forms** — `https://github.com/<owner>/<repo>` (also `http://`, `www.`, without a scheme, with `.git`, a trailing path, query or fragment), `git@github.com:<owner>/<repo>.git` and a bare `<owner>/<repo>`. An absolute Windows path is still a folder; anything else is search text.
- **Suggestions** — with a connected account, search text lists up to 8 of the account's repositories (owner, collaborator, organisation member; newest push first) whose `owner/name` contains every typed word; **↑/↓**, **Enter** and **Esc** work as in any list. Without an account the list offers **GitHub verbinden …** (connect GitHub). A pasted URL or typed `owner/name` needs no account.
- **Clone or reuse** — a repository starts in `<Klon-Ordner>\<owner>\<name>` (default `%USERPROFILE%\Traygent`). An existing folder is reused as it is, and ▶ on a „Workspaces“ entry keeps using that entry's folder while it exists, even after the Klon-Ordner changed; otherwise the session's own terminal runs `git clone` first, so progress, Git Credential Manager prompts and errors show where the session runs, and a failed clone stops before the agent starts. Docker sessions clone on the host and bind-mount the folder. Git must be installed.
- **One account** — a personal access token or an imported `gh` sign-in (read only after **Übernehmen**), verified against GitHub's `/user`. The token lives in the Windows Credential Manager, never in `state.json`; Traygent uses it for the repository list and, with **GitHub-Token weitergeben** enabled, for Docker sessions. Host clones use Windows Git authentication. **Trennen** removes Traygent's copy; `gh` stays signed in.
- **Limits** — repositories outside the account's list are found only when typed as `owner/name` or pasted as a URL; a repository created since the last list read appears after **Aktualisieren**; a token rotated in `gh` must be imported again.
- **The list** — read at startup, after connecting, on **Aktualisieren** and when the field gets focus with a list older than 15 minutes; at most 1000 repositories, kept in memory only.

## Several accounts — „Profile“

Claude Code can keep several sign-ins side by side, say a private and a team subscription ([ADR-0009](adr/0009-agent-profiles-with-linked-config-directories.md)). Each profile has its own login; skills, agents, commands, plugins, settings, MCP servers and history stay the same in all of them ([ADR-0010](adr/0010-three-way-merge-of-the-profiles-settings-and-state-file.md)).

1. **Add** — **Einstellungen → Agenten → Claude Code → Profile**: type a name into **Neues Profil** and press **Enter** or **+**: the profile is saved at once and can sign in right away (other changes in the dialog still wait for **Speichern**). A click on a profile's name opens its details in place: name (a rename waits for **Speichern**), account, organisation, folder, last sync. The name gives the folder `%USERPROFILE%\.claude-<name>` (the field's tooltip shows it); a profile named **Team** adopts an existing `.claude-team` together with its login. A folder of that name that is not a Claude Code folder (no `.claude.json`, no login) is left alone: the row says „Profilordner gehört nicht zu Claude Code“ and the profile neither starts nor signs in — pick another name.
2. **Sign in** — **Anmelden** on a signed-out profile's row runs `claude auth login` for that profile without a window: the browser opens, you sign in there, and the row turns to the account by itself (a 3 s „Angemeldet.“). While it waits the row's button is a spinning icon — a click on it cancels; after 5 minutes it gives up („Anmeldung abgelaufen.“); quitting Traygent ends it too. A failure stays as a red line under the list, named after the profile, until that profile signs in again or you sync or add a profile. A signed-in row has no **Anmelden**; **Neu anmelden** sits in its details. When two profiles are signed in with the same e-mail address in different organisations, each row shows its organisation instead (the tooltip shows both). If the sign-in needs a code pasted into the terminal (the browser cannot reach Traygent's machine), switch on **Einstellungen → App → Fehlersuche → Debug**: **Anmelden** then opens the visible terminal, which stays open so every line can be read, and the row still updates by itself once the sign-in lands (watched for up to 10 minutes).
3. **Pick** — **Standard-Profil** sets the one new sessions start with; the composer's **Profil** chip changes it for the next start, and a „Workspaces“ row restarts with the profile it last used.
4. **What stays in sync** — the folders `skills`, `agents`, `commands`, `rules`, `output-styles`, `workflows`, `agent-memory`, `themes`, `plugins`, `projects`, `file-history`, `plans`, `tasks`, `paste-cache`, `hooks`, `todos` and `session-env` are links into **Standard**'s, so every profile sees the same files at every moment. The rest is synced before each Claude start, after a profile change, at app start, on **Jetzt synchronisieren** and in the background every 15 minutes — so a change made in a running session reaches the other profiles with the next start through Traygent: `CLAUDE.md` and `keybindings.json` as whole files (the newer one wins), `history.jsonl` as the union of both, and `settings.json` and the MCP servers, projects and the switches `showSpinnerTree` and `claudeInChromeDefaultEnabled` of `.claude.json` merged setting by setting — what you change in one profile, add or remove, reaches the others, and changes both made to different settings both survive.
5. **What stays per profile** — the login (`.credentials.json`) and the account data of `.claude.json`; in `settings.json` everything that picks an account, routes requests or reports to an organisation (`forceLoginOrgUUID`, `forceLoginMethod`, `apiKeyHelper`, `otelHeadersHelper`, the AWS and Anthropic profile keys, and in `env` the `ANTHROPIC_…`, `CLAUDE_CODE_USE_…`, `AWS_…`, `GOOGLE_…`, `AZURE_…`, `OTEL_…`, `VERTEX_REGION_…`, `CLAUDE_CODE_CLIENT_…` and `CLAUDE_CODE_SKIP_…_AUTH` variables, `CLOUD_ML_REGION`, `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_OAUTH_TOKEN`); proxy variables (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`) are shared on purpose — they belong to the machine, not the account; in a project the `last…` fields (last session, cost) and `hasUnseenTeamArtifacts`.
6. **Share more** — **Weitere Ordner** and **Weitere Dateien** (shown once there is a second profile) take extra names inside the Claude Code folder (**Bereits abgeglichen** below them lists the built-in ones), separated by commas or spaces, e.g. `.caveman-sessions` or `orca-state.json`. An extra folder is linked like the built-in ones; an extra file is copied whole, the newer one winning — it is never merged, so two profiles that both changed it keep only the newer edit (the other is in the backup). Plain names only (letters, digits, `.`, `_`, `-`, at most 16 each); a name the sync already handles, the login and state files (and anything named after them, such as `.claude.json.backup`) and the account's caches and logs (`cache`, `statsig`, `telemetry`, `sessions`, `policy-limits.json` and the like) are refused on **Speichern**.

On a profile's first sync **Standard** wins, but nothing is lost: a folder of the profile first hands over what **Standard** lacks, settings, MCP servers and projects only one side has are added to the other, and every file a sync overwrites or takes something from — later too, on either side — is first copied to `.traygent-backup\<time>` in the folder it belongs to (**Standard**'s in `%USERPROFILE%\.claude`). Backups are never cleaned up. Later, where both profiles changed the same setting differently, the newer file wins and the other value stays in the backup. A new profile learns from the others what **Standard** removed and drops it where it still holds the old value; what it changed or added itself is kept and reaches every profile. A setting, MCP server or project removed in one profile is removed in the others with the next sync; a copied file or a history line deleted in one profile is not, the next sync brings it back. A file a running session just wrote is left for the next sync. A sync that fails shows a warning icon on the row (its tooltip says why) and „Profile konnten nicht vollständig synchronisiert werden.“ after **Starten**; the session starts anyway. Docker mounts the selected profile read-write and makes its shared folders available at their usual paths. Removing a profile leaves its folder and login on disk.

## Docker sessions

- Docker runs the agent in `node:22-trixie` (configurable under **Umgebung**). A folder and a cloned repository both enter the container as a writable workspace.
- **Node-Version mit mise** under **Einstellungen → Umgebung → Docker** is on by default. A project can select its Linux Node with `.nvmrc` or `.node-version`. Traygent reuses a matching image runtime or caches the download for the agent. Turn the switch off to use the image's Node.
- **Claude Code** uses the selected profile's file-based credentials, skills and global state. When its user settings contain Windows Node hooks with an argument list, Traygent creates a read-only settings copy for that session. The hook receives Linux paths for files in the mounted profile and workspace. With mise enabled, a hook pinned to an exact NVM version gets that Linux version. Edit projected user settings on Windows and restart the session. A script stored only in Standard must also be available to the selected profile through its shared folders.
- **Codex** shares the host Codex home, including `auth.json` and `config.toml`. Both agents can refresh their file-based credentials through the directory mount. Other Windows-specific hook commands and MCP programs need Linux equivalents. Accounts stored exclusively in a Windows credential vault are outside the mount.
- Each Linux CLI stays in its own tools volume. On startup Traygent checks that Codex actually runs and repairs a broken install. When the host has no Codex login, the container can sign in using device auth or `OPENAI_API_KEY` forwarded by name.
- Existing `claude-code-config` and `traygent-codex-home` volumes keep their old Docker-only configuration. Traygent now uses the host files for these agents. OpenCode continues to keep its state in named volumes. Each agent mounts the folder at `/workspace/<project-name>` so projects have distinct working directories. Codex keeps its Linux SQLite databases in the tools volume to allow concurrent local and container sessions.
- Git inside the container gets `safe.directory=*`, `core.autocrlf=input` and your `%USERPROFILE%\.gitconfig` read-only. Traygent makes the Linux GitHub CLI (`gh`) available alongside Git, reusing a working installation or installing it on the first start. With **GitHub-Token weitergeben** enabled, both use the account connected under **Einstellungen → GitHub** for GitHub HTTPS operations. Switching the active Windows `gh` account leaves this selection in place. Connecting a different account applies to new sessions. If the gh download is unavailable, Git can still use the forwarded token for GitHub HTTPS.
- **Docker-Socket durchreichen** mounts the host's `/var/run/docker.sock` into new Docker sessions, so the agent can run `docker` against your host's engine — that is control over the host's Docker, so it is off by default. The first such start installs the static Docker CLI into the agent's tools volume; without a socket on the engine the session prints a notice and starts anyway. A „Workspaces“ row keeps the choice it started with; change it with **Bearbeiten …**.
- Network and WSL paths (`\\server\share`, `\\wsl$\…`) cannot be bind-mounted and are refused.

## Where Traygent keeps its state

Settings, recent sessions and the connected GitHub account's login and id live in one versioned JSON file, `%APPDATA%\io.github.fo0.traygent\state.json`, written atomically ([ADR-0002](adr/0002-versioned-json-state-file.md)). A corrupt file is moved aside as `state.json.corrupt-<timestamp>` and replaced by defaults; a file from a newer Traygent is read but never overwritten. The theme stays in the panel's local storage; the GitHub token stays in the Windows Credential Manager (entry `traygent`, user `github-<id>`).
