# Architecture

Traygent uses a Svelte 5/TypeScript panel and a Tauri 2/Rust desktop service. There is no application server. The panel never spawns processes or reaches the network; detection, launching, persistence and the GitHub account live in Rust. Product and IPC contract: [SPEC.md](SPEC.md); per-agent flags and Docker recipes: [AGENT_RECIPES.md](AGENT_RECIPES.md).

```text
Svelte panel ── src/lib/ipc.ts ── Tauri IPC (camelCase JSON) ── desktop_agents.rs / desktop_github.rs / desktop.rs commands
                                                                  ├── Service (traygent_core::service)
                                                                  │   ├── store    state.json (settings, recents, GitHub account metadata)
                                                                  │   ├── detect   CLIs + Docker, own thread → traygent:snapshot
                                                                  │   ├── repo     folder field classification, clone folder
                                                                  │   ├── launch   pure argv builder (PowerShell script, git clone, docker run)
                                                                  │   ├── profiles config dir per sign-in, links + merge/file sync with the default home
                                                                  │   └── spawn    wt.exe or a console → powershell.exe → [git clone] → CLI or docker
                                                                  └── github   /user, /user/repos (own thread → traygent:snapshot), gh import, OS vault
```

The module-level diagram is [ARCHITECTURE.mmd](ARCHITECTURE.mmd) (Mermaid). Decisions: [ADR-0002](adr/0002-versioned-json-state-file.md) (state file), [ADR-0003](adr/0003-launch-through-a-powershell-argv.md) (launch argv), [ADR-0004](adr/0004-docker-volumes-shared-with-the-batch-starter.md) (Docker volumes), [ADR-0005](adr/0005-start-from-a-github-repository.md) (start from a GitHub repository), [ADR-0006](adr/0006-default-clone-root-in-a-traygent-folder.md) (default clone root), [ADR-0007](adr/0007-persisted-environment-visibility.md) (environment visibility), [ADR-0008](adr/0008-background-updates-of-the-agent-clis.md) (agent CLI updates), [ADR-0009](adr/0009-agent-profiles-with-linked-config-directories.md) (agent profiles), [ADR-0010](adr/0010-three-way-merge-of-the-profiles-settings-and-state-file.md) (profile merge and extra shared entries).

**Desktop binary `traygent`** (feature `desktop`): `main.rs` starts `desktop.rs`, which registers the plugins (single-instance, dialog, opener, updater), the IPC commands and the tray icon. ## Detection

Setup and `refresh_detection` call `start_detection`: unless one already runs, `Service::begin_detection` sets `detecting: true` and a new thread runs `detect::detect` (local CLIs and the Docker engine in parallel; when the engine is ready, `docker volume inspect` / `docker image inspect` per agent to announce a first install or pull). `refresh_detection` returns at once with `detecting: true`; before `finish_detection` the thread reads every profile's status — the first detection after start syncs the profiles instead (`desktop_profiles.rs → read_or_sync`, a panic there keeps the previous statuses); `finish_detection` stores the result (a panicked run keeps the previous one) and the shell emits `traygent:snapshot` with the finished snapshot, which `bridge.ts` hands to the panel.

## GitHub account and repository listing

1. **Connect.** `github_connect_token { token }` or, after „Lokale Anmeldung prüfen“ (`github_local_accounts`, reads no token) and „Übernehmen“, `github_import_local { login }` (`gh auth token --hostname github.com --user <login>`). Either verifies the token against `GET /user` (an import must name the chosen login) and writes it to the OS vault (service `traygent`, user `github-<id>`) — all on a worker thread. `Service::connect_github` then records `{ login, id, source }` in `state.json` (another account's vault entry is deleted) and begins a listing.
2. **List.** At startup, after connecting, on `github_refresh_repos` and when the panel focuses the folder field with a listing older than 15 minutes, `start_listing` begins one unless one runs (`github.loading: true`). A `traygent-github` thread reads the token from the vault and pages `GET /user/repos?affiliation=owner,collaborator,organization_member&sort=pushed&per_page=100` along `Link: rel="next"`; `finish_listing` stores it (or `github.error`, keeping the last repositories) unless the account changed meanwhile, and the shell emits `traygent:snapshot`. The listing lives in memory only.
3. **Search.** The panel filters `github.repos` locally (`target.ts → matchRepos`); no request per keystroke.
4. **Disconnect.** `github_disconnect` deletes the vault entry and forgets the account and its listing; gh stays signed in.

## Launch pipeline

1. The panel sends `launch_session { request }` (agent, env, folder or `repo` with folder `''`, options, session, `profile` when Lokal and not `default`).
2. `Service::prepare_launch` (`service/launch_prep.rs`) validates a `repo` and derives the folder `<clone root>\<owner>\<name>`; when that folder is missing it marks the start as a clone and resolves `git.exe`. Otherwise it normalizes the folder (absolute, no control chars, no trailing `\`), checks it exists, resolves the CLI (the detection's choice while it still exists, else the first candidate), `docker.exe`, `gh.exe` (only with the gh-token switch), `.gitconfig`, `powershell.exe` and `wt.exe`. A profile other than `default` must be listed and resolves to its directory through `Homes` (local only; Docker drops it).
3. `launch::plan` (or `launch::clone_plan` for a clone, which runs the terminal in the clone root) validates options and environment and builds the PowerShell script: window title, for a clone `& '<git.exe>' 'clone' '--' 'https://github.com/<owner>/<name>.git' '<folder>'` and a `throw` on a non-zero `$LASTEXITCODE`, `Set-Location -LiteralPath`, Base64 env (`OPENCODE_CONFIG_CONTENT`, `TRAYGENT_INIT`, the git helper), the profile's `$env:CLAUDE_CONFIG_DIR` (or its `Remove-Item` for the default profile while extra ones exist), then `& '<cli>' '<arg>' …` locally or `& '<docker.exe>' 'run' … '<image>' 'bash' '-c' '<loader>' 'traygent' <agent args>`, inside one `try`/`finally` (`run_agent`) that closes the terminal after a normal end (exit code 0, 130, `0xC000013A` or Ctrl+C) and otherwise prints the exit code and stays open.
4. `wrap` turns it into `powershell.exe -NoLogo -NoExit -EncodedCommand <Base64 UTF-16LE script>`, inside `wt.exe [-w traygent] new-tab -d <folder> --title <title> --suppressApplicationTitle …` when Windows Terminal is selected and found (`-w traygent` with `sharedWindow`) (`-d` is dropped for a folder with `;` or `%`, the title replaces them).
5. For a clone, the clone root is created only after the plan is built. A local start of an agent with extra profiles first syncs that agent's profiles without the service lock (`launch_sync_plan` → `run_plan` → `finish_launch_sync`; failures become the one-sentence `LaunchOutcome.warning`, only a requested profile directory that cannot be created or belongs to something else stops the start). `spawn::spawn` starts it; a failed `wt.exe` start falls back to the console plan. Only after a successful spawn is the recent session recorded and `state.json` written; the popup then hides so the terminal gets the focus.

`install_agent` uses the same wrapper for the catalog install command in the user profile (`-ExecutionPolicy Bypass`, process scope), only on an explicit click; `profile_login` with „Debug“ likewise for `<cli> auth login` in the profile's environment; without it the same lines run in a hidden `powershell.exe -NoProfile -NonInteractive -EncodedCommand` (`launch/login.rs → hidden_login_plan`).

## Trust boundaries

- **Panel → Rust.** Every IPC argument is untrusted input: Rust re-validates the folder, model, effort, extra arguments (no quotes or control chars; with an npm `.cmd` shim none of `& | < > ^ % !`), Docker images and the environment, whatever the panel checked. German `Err` strings return verbatim.
- **Rust → terminal.** No shell string: an argv whose script holds only single-quoted literals and Base64 ([ADR-0003](adr/0003-launch-through-a-powershell-argv.md)). CLIs run by absolute path.
- **Host → container.** Only the chosen folder is bind-mounted (network and WSL paths refused) plus `.gitconfig` read-only; state lives in named volumes. The gh token is fetched inside the session and forwarded by name only, never in a command line, the snapshot or `state.json`; `OPENAI_API_KEY` is forwarded by name only when set.
- **GitHub token.** Read only from the user (pasted) or from gh after an explicit „Übernehmen“; held as a `SecretToken` (never printed or serialized, wiped on drop), stored only in the OS vault, sent only as a bearer header to `https://api.github.com` (no redirects). It never reaches `state.json`, the snapshot, a command line, an environment variable or the clone — `git clone` uses the user's own Git credentials (Git Credential Manager). gh runs by canonical absolute path (outside the working directory and any Git checkout) with a minimal environment, closed stdin, capped output and a timeout. Repository names from GitHub and the panel are validated before they reach a path or a clone URL.
- **Rust → the agent's config directories.** The profile sync writes only below paths `Homes` builds from the user profile, the recipe's fixed names and a validated id, plus the user's extra names, which pass `profiles/share.rs → check_name` again before they are joined. It never reads `.credentials.json` (existence and size only); the own keys and `env` variables of `settings.json` (the recipe's `SettingsRule`), every `.claude.json` key outside the shared subset (`mcpServers`, `projects` without their `last…` / `hasUnseenTeamArtifacts` fields, `showSpinnerTree`, `claudeInChromeDefaultEnabled`) and the own project fields never leave their profile or reach a base. The bases in `.traygent-base` hold values (MCP server commands and `env` included) and stay in their own profile's directory. It deletes nothing but an empty directory that makes room for a link; whatever a rule overwrites or takes something from goes to the `.traygent-backup` of the home it came from, and a non-empty directory that is not a Claude Code configuration directory is never touched.
- **Webview.** Local assets under a restrictive CSP and no shell capability; `src-tauri/capabilities/default.json` grants the panel window only event listening and header dragging.

## External dependencies

- `api.github.com` — unauthenticated for the release check (`updates.rs`), authenticated with the user's token for `/user` and `/user/repos` (`github/api.rs`).
- `git` — `git clone` in the session's terminal, credentials by the user's Git setup.
- `gh` — optional; its sign-ins are listed and one token is imported on consent.
- OS credential vault (`keyring`, Windows Credential Manager) — the GitHub token.
