# Architecture

Traygent uses a Svelte 5/TypeScript panel and a Tauri 2/Rust desktop service. There is no application server. The panel never spawns processes or reaches the network; detection, launching, persistence and the GitHub account live in Rust. Product and IPC contract: [SPEC.md](SPEC.md); per-agent flags and Docker recipes: [AGENT_RECIPES.md](AGENT_RECIPES.md).

```text
Svelte panel ── src/lib/ipc.ts ── Tauri IPC (camelCase JSON) ── desktop_agents.rs / desktop_github.rs / desktop.rs commands
                                                                  ├── Service (traygent_core::service)
                                                                  │   ├── store    state.json (settings, recents, GitHub account metadata)
                                                                  │   ├── detect   CLIs + Docker, own thread → traygent:snapshot
                                                                  │   ├── repo     folder field classification, clone folder
                                                                  │   ├── launch   pure argv builder (PowerShell script, git clone, docker run)
                                                                  │   └── spawn    wt.exe or a console → powershell.exe → [git clone] → CLI or docker
                                                                  └── github   /user, /user/repos (own thread → traygent:snapshot), gh import, OS vault
```

The module-level diagram is [ARCHITECTURE.mmd](ARCHITECTURE.mmd) (Mermaid). Decisions: [ADR-0002](adr/0002-versioned-json-state-file.md) (state file), [ADR-0003](adr/0003-launch-through-a-powershell-argv.md) (launch argv), [ADR-0004](adr/0004-docker-volumes-shared-with-the-batch-starter.md) (Docker volumes), [ADR-0005](adr/0005-start-from-a-github-repository.md) (start from a GitHub repository), [ADR-0006](adr/0006-default-clone-root-in-a-traygent-folder.md) (default clone root), [ADR-0007](adr/0007-persisted-environment-visibility.md) (environment visibility).

## Panel (`src/`)

`App.svelte` wires the app bar, the status banners, the dashboard, the footer, the settings dialog, keyboard shortcuts and the update timer. State and mutations live in controllers under `src/lib/`, so dialogs keep only form state:

| Controller                | Responsibility                                                                                                                                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `panel.svelte.ts`         | Snapshot, load error, refresh (`refreshDetection`), launch, install, remove with 8 s „Rückgängig“ (`restoreRecent`), the general notice; owns `github`                                                                                                                                                |
| `composerState.svelte.ts` | The „Neue Session“ form: starts from the saved defaults and the newest recent target (its repository, else its folder); the field text is classified by `target.ts`, a repository start sends `repo` with folder `''`; changes apply to the next start only                                           |
| `settingsDraft.svelte.ts` | Staged settings of „Agenten“, „Umgebung“ and the „GitHub“ clone root; „Speichern“ sends the whole object once (`save_settings`), „Abbrechen“ drops it                                                                                                                                                 |
| `githubActions.svelte.ts` | Settings → GitHub account actions that apply at once (connect by token, list and import gh sign-ins, disconnect) and the listing refresh, incl. the at-most-once-per-15-min refresh when the folder field gets focus with a stale listing; lives in the panel so a closed dialog never drops a result |
| `notices.svelte.ts`       | Banner notices, one per key; successes close after 3 s, an action notice keeps its own timeout, warnings and errors stay                                                                                                                                                                              |
| `modals.svelte.ts`        | Which dialog is open, its initial settings tab and where focus returns                                                                                                                                                                                                                                |
| `updater.svelte.ts`       | Update check and one `install_update` call (download, verify, install) with progress stages                                                                                                                                                                                                           |
| `autostart.svelte.ts`     | Windows autostart while Settings is open: reads the OS state, stages the switch, writes it on **Speichern**; repair actions act at once                                                                                                                                                               |

Pure helpers: `agents.ts` (labels, icons, the permission cycle, path parts, whether a start can run — generic over the catalog), `target.ts` (classifies the folder field's text as folder / repository / search with the shared vectors of `fixtures/targets.json`, matches the listing — at most 8, every word in `owner/name` — and decides when a listing is stale), `recents.ts` (the „Zuletzt“ rules the demo and the undo mirror), `optionMarks.ts` (a model's badge letter, an effort's filled bars), `environments.ts` (which environments the composer shows, the fallback from a hidden one and the last-one lock, mirroring the Rust rules), `validation.ts` (early field checks; Rust validates again and has the last word), `format.ts` / `clock.ts` (relative times).

`src/lib/ipc.ts` is the only module that invokes native commands: `call()` is typed by a `Commands` map of every command registered in `generate_handler!` (`src-tauri/src/desktop.rs`); `ipc.contract.test.ts` pins the map to the handler list in both directions, checks each command's argument names against its Rust parameters and fails if any other file calls Tauri's `invoke`. `bridge.ts` selects native IPC (plus the `traygent:snapshot` event subscription) or the browser demo (`demo.ts` + `demoData.ts` + `demoRecents.ts` + `demoGithub.ts` with an invented `demo-…` account, repositories and gh sign-ins, always labelled „Demo“); both serve the `Bridge` interface in `bridgeTypes.ts`. `types.ts` is the contract that `src-tauri/src/models.rs` mirrors.

Components: `AppBar` (brand, refresh, settings), `Dashboard` with `Composer` (`Segmented` agent and environment controls with product marks and status dots, `FolderField` — a combobox for a folder or a repository with browse, recent folders, a GitHub menu of recent repositories and the `RepoSuggestions` listbox (or „GitHub verbinden …“ without an account) — `OptionChips` Modell / Denken / Freigabe / Session through `Dropdown` (select-only combobox) and `ModelCombo` (free model strings), both opening the shared `ChoiceList`, **Starten** or **Installieren …**) and `RecentList` / `RecentRow` (`AgentBadge` with the agent's product mark on a tile, `RecentMeta` with the fixed columns at the right edge — ports, repository, environment, model, thinking, permission, time; an absent part keeps its empty column — `ModelBadge` with the model's letter and the `signal` bars of the thinking level, the row-wide ▶ restart guarded by `rowStart.ts` (one start per press), the GitHub mark for a start from GitHub, „⋯“ menu via `menu.ts`; „Bearbeiten …“ opens `RecentEditDialog` with the same `OptionFields` and, for Docker, `PortPicker`), `AppFooter` (Docker line, „Stand hh:mm“), `StatusBanners` + `NoticeBanner`, `SettingsDialog` (tabs from `settingsTabs.ts`: „Agenten“ = `AgentSettings` + `AgentDefaults` (the shared `OptionFields`, same `Dropdown` / `ModelCombo` as the chips) + `CopyField`, „Umgebung“ = `EnvSettings`, „GitHub“ = `GithubSettings` (account, „Aktualisieren“, „Trennen“ via `InlineConfirm`, „Klon-Ordner“) + `GithubConnect` (gh import, token field), „App“ = `ThemeSetting`, `StartupSettings`, „Updates“ = `UpdatePanel`), `Modal` (focus trap via `focus.ts`), `SectionHeader`, `EmptyState`, `Icon` (line glyphs plus the product marks of `brandGlyphs.ts`, docs/ASSETS.md). `shortcuts.ts` maps F5 / Ctrl+R to refresh and suppresses the webview reload. Styles live in ordered files under `src/styles/`; every colour is a token in `00-tokens.css`. `theme.ts` keeps **Darstellung** in localStorage (`traygent.theme.v1`).

**Desktop binary `traygent`** (feature `desktop`): `main.rs` starts `desktop.rs`, which registers the plugins (single-instance, dialog, opener, updater), the IPC commands and the tray icon. `NativeState` holds `Mutex<Service>`, opened on the app data dir at setup (read-only defaults when there is none); `work()` runs a command's blocking work on a worker thread with exclusive access to it. `desktop_agents.rs` holds the agent-domain commands (`save_settings`, `launch_session`, `remove_recent`, `restore_recent`, `update_recent`, `pick_folder`, `install_agent`, `open_folder`) and `start_detection`. `desktop_github.rs` holds the GitHub commands (`github_connect_token`, `github_local_accounts`, `github_import_local`, `github_disconnect`, `github_refresh_repos`) and `start_listing`; their network, gh and vault calls run on blocking worker threads without the service lock, the service only commits the results. `desktop_startup.rs` is the Windows Run-value adapter, `desktop_updates.rs` the update commands, `tray_popup.rs` / `tray_popup/windows.rs` the window lifecycle and Win32 integration.

## Detection

Setup and `refresh_detection` call `start_detection`: unless one already runs, `Service::begin_detection` sets `detecting: true` and a new thread runs `detect::detect` (local CLIs and the Docker engine in parallel; when the engine is ready, `docker volume inspect` / `docker image inspect` per agent to announce a first install or pull). `refresh_detection` returns at once with `detecting: true`; `finish_detection` stores the result (a panicked run keeps the previous one) and the shell emits `traygent:snapshot` with the finished snapshot, which `bridge.ts` hands to the panel.

## GitHub account and repository listing

1. **Connect.** `github_connect_token { token }` or, after „Lokale Anmeldung prüfen“ (`github_local_accounts`, reads no token) and „Übernehmen“, `github_import_local { login }` (`gh auth token --hostname github.com --user <login>`). Either verifies the token against `GET /user` (an import must name the chosen login) and writes it to the OS vault (service `traygent`, user `github-<id>`) — all on a worker thread. `Service::connect_github` then records `{ login, id, source }` in `state.json` (another account's vault entry is deleted) and begins a listing.
2. **List.** At startup, after connecting, on `github_refresh_repos` and when the panel focuses the folder field with a listing older than 15 minutes, `start_listing` begins one unless one runs (`github.loading: true`). A `traygent-github` thread reads the token from the vault and pages `GET /user/repos?affiliation=owner,collaborator,organization_member&sort=pushed&per_page=100` along `Link: rel="next"`; `finish_listing` stores it (or `github.error`, keeping the last repositories) unless the account changed meanwhile, and the shell emits `traygent:snapshot`. The listing lives in memory only.
3. **Search.** The panel filters `github.repos` locally (`target.ts → matchRepos`); no request per keystroke.
4. **Disconnect.** `github_disconnect` deletes the vault entry and forgets the account and its listing; gh stays signed in.

## Launch pipeline

1. The panel sends `launch_session { request }` (agent, env, folder or `repo` with folder `''`, options, session).
2. `Service::prepare_launch` (`service/launch_prep.rs`) validates a `repo` and derives the folder `<clone root>\<owner>\<name>`; when that folder is missing it marks the start as a clone and resolves `git.exe`. Otherwise it normalizes the folder (absolute, no control chars, no trailing `\`), checks it exists, resolves the CLI (the detection's choice while it still exists, else the first candidate), `docker.exe`, `gh.exe` (only with the gh-token switch), `.gitconfig`, `powershell.exe` and `wt.exe`.
3. `launch::plan` (or `launch::clone_plan` for a clone, which runs the terminal in the clone root) validates options and environment and builds the PowerShell script: window title, for a clone `& '<git.exe>' 'clone' '--' 'https://github.com/<owner>/<name>.git' '<folder>'` and a `throw` on a non-zero `$LASTEXITCODE`, `Set-Location -LiteralPath`, Base64 env (`OPENCODE_CONFIG_CONTENT`, `TRAYGENT_INIT`, the git helper), then `& '<cli>' '<arg>' …` locally or `& '<docker.exe>' 'run' … '<image>' 'bash' '-c' '<loader>' 'traygent' <agent args>`, inside one `try`/`finally` (`run_agent`) that closes the terminal after a normal end (exit code 0, 130, `0xC000013A` or Ctrl+C) and otherwise prints the exit code and stays open.
4. `wrap` turns it into `powershell.exe -NoLogo -NoExit -EncodedCommand <Base64 UTF-16LE script>`, inside `wt.exe [-w traygent] new-tab -d <folder> --title <title> --suppressApplicationTitle …` when Windows Terminal is selected and found (`-w traygent` with `sharedWindow`) (`-d` is dropped for a folder with `;` or `%`, the title replaces them).
5. For a clone, the clone root is created only after the plan is built. `spawn::spawn` starts it; a failed `wt.exe` start falls back to the console plan. Only after a successful spawn is the recent session recorded and `state.json` written; the popup then hides so the terminal gets the focus.

`install_agent` uses the same wrapper for the catalog install command in the user profile (`-ExecutionPolicy Bypass`, process scope), only on an explicit click.

## Trust boundaries

- **Panel → Rust.** Every IPC argument is untrusted input: Rust re-validates the folder, model, effort, extra arguments (no quotes or control chars; with an npm `.cmd` shim none of `& | < > ^ % !`), Docker images and the environment, whatever the panel checked. German `Err` strings return verbatim.
- **Rust → terminal.** No shell string: an argv whose script holds only single-quoted literals and Base64 ([ADR-0003](adr/0003-launch-through-a-powershell-argv.md)). CLIs run by absolute path.
- **Host → container.** Only the chosen folder is bind-mounted (network and WSL paths refused) plus `.gitconfig` read-only; state lives in named volumes. The gh token is fetched inside the session and forwarded by name only, never in a command line, the snapshot or `state.json`; `OPENAI_API_KEY` is forwarded by name only when set.
- **GitHub token.** Read only from the user (pasted) or from gh after an explicit „Übernehmen“; held as a `SecretToken` (never printed or serialized, wiped on drop), stored only in the OS vault, sent only as a bearer header to `https://api.github.com` (no redirects). It never reaches `state.json`, the snapshot, a command line, an environment variable or the clone — `git clone` uses the user's own Git credentials (Git Credential Manager). gh runs by canonical absolute path (outside the working directory and any Git checkout) with a minimal environment, closed stdin, capped output and a timeout. Repository names from GitHub and the panel are validated before they reach a path or a clone URL.
- **Webview.** Local assets under a restrictive CSP and no shell capability; `src-tauri/capabilities/default.json` grants the panel window only event listening and header dragging.

## External dependencies

- `api.github.com` — unauthenticated for the release check (`updates.rs`), authenticated with the user's token for `/user` and `/user/repos` (`github/api.rs`).
- `git` — `git clone` in the session's terminal, credentials by the user's Git setup.
- `gh` — optional; its sign-ins are listed and one token is imported on consent.
- OS credential vault (`keyring`, Windows Credential Manager) — the GitHub token.

## Desktop and updates

The stable app ID is `io.github.fo0.traygent`. Closing the panel keeps it in the tray; **Traygent beenden** exits. Optional Windows login startup uses a guarded per-user Run value as its source of truth; the `--autostart` launch keeps the window hidden ([WINDOWS_AUTOSTART.md](WINDOWS_AUTOSTART.md)).
