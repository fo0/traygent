# Asset sources

The application icons and UI glyphs of Traygent are constructed from basic lines, circles and rectangles. The only imported artwork are the product marks listed under _Product marks_; no font glyph or previous raster image is an input. The project license is unchanged.

## Application icons

`scripts/generate-icons.mjs` defines a violet rounded tile with a dark robot head (antenna, ears, two eyes and a mouth cut out in the tile colour) on a 64-unit canvas. That geometry and its colors are the editable source. The same definitions produce `src-tauri/icons/source.svg`, the 32, 128 and 256px PNGs, and a Windows ICO containing 16, 32, 48, 64, 128 and 256px PNG frames.

```sh
pnpm icons:generate
pnpm icons:check
```

The generator uses only Node.js standard-library file operations and its own geometric sampler/PNG/ICO writer. Four samples per axis provide edge coverage. RGBA PNGs use stored DEFLATE blocks, fixed scan order and no timestamps or text metadata, making output independent of compression-library versions. No network, image package or platform font is required. `icons:check` compares the derived bytes with the tracked files and is part of `pnpm verify`.

## UI and tray glyphs

`src/lib/Icon.svelte` contains the UI glyphs as explicit SVG primitives on a 24-unit canvas. The brand glyph `robot` echoes the application icon. The thinking-level glyph `signal` (five bars, `level` of them filled, the rest at 30 % opacity) has its own 14-unit grid, so each bar is 2 px wide with 1 px gaps at 14 px.

## Product marks

`src/lib/brandGlyphs.ts` holds single-path marks of the tools Traygent starts or reaches, drawn filled in `currentColor` through `Icon.svelte` (class `mark-<name>`). They identify those products next to their names (nominative use) and imply no endorsement; the trademarks belong to their owners. Only Claude has a colour of its own, the token `--brand-claude`; the others follow the text colour.
