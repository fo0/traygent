## Runtime environment read by the app

Traygent sets none of these; it reads them from its own process to find tools: `PATH` (plus the registry User and Machine `Path`), `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `ProgramFiles`, `SystemRoot`, `CODEX_INSTALL_DIR` (`src-tauri/src/detect/host.rs`). `OPENAI_API_KEY` is forwarded to a Codex container by name only, when the user's environment sets it (`launch/docker.rs`). `USERPROFILE` also gives the default clone root `%USERPROFILE%\Traygent` (`repo.rs`, ADR-0006). To find gh.exe, `github/discover.rs` additionally reads `ProgramW6432`, `ProgramFiles(x86)`, `ProgramData`, `SCOOP`, `SCOOP_GLOBAL` and `ChocolateyInstall`. gh runs with a minimal environment (`github/process.rs → KEPT`: profile, app data, temp, proxy and CA variables, plus `GH_CONFIG_DIR` when absolute); `GH_TOKEN` / `GITHUB_TOKEN`, `GH_HOST`, `GIT_*` and askpass settings never reach it.

## Secrets Locations

Secrets are never committed. No secret is needed to build or test. The release workflow uses only the repository `GITHUB_TOKEN`; any further CI secret belongs in the CI secret store. Demo data and captures are synthetic. No `.env` file is used; a local one would stay gitignored. A new secret gets a placeholder in `.env.example` and a question to the user — never `gh secret set` unprompted. A host gh token passed into an agent container (opt-in, `docker.ghToken`) is fetched with `gh auth token` inside the launched session, forwarded by name only (`-e GH_TOKEN`) and removed from the session afterwards; it never reaches a command line, the snapshot or `state.json`. The GitHub account's token (pasted, or imported from gh after „Übernehmen“) lives only in the OS credential vault (service `traygent`, user `github-<id>`), never in `state.json`, the snapshot, a command line, an environment variable or a clone; Docker's `docker.ghToken` switch is separate and still reads `gh auth token` in the session. Agent logins live in the agents' own config dirs or Docker volumes, never in Traygent's files.
