## Runtime environment read by the app

Traygent sets none of these; it reads them from its own process to find tools: `PATH` (plus the registry User and Machine `Path`), `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `ProgramFiles`, `SystemRoot`, `CODEX_INSTALL_DIR` (`src-tauri/src/detect/host.rs`). `CODEX_HOME` and `CLAUDE_CONFIG_DIR` select the host CLI directories for Docker (see ADR-0011). For the OpenCode Go quota, `quota_paths.rs → opencode_database()` follows the CLI's own `OPENCODE_DB` (optional; unset means `opencode.db`, an absolute path is used as is, a relative one is taken inside the CLI's data directory; empty, `:memory:` and on Windows a root- or drive-relative one read nothing) and `XDG_DATA_HOME` (optional; the data directory is `<XDG_DATA_HOME>\opencode`, unset or empty `%USERPROFILE%\.local\share\opencode`), both read in `detect/host.rs`. Docker forwards `OPENAI_API_KEY` to Codex and `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` to Claude by name when the environment provides them (`launch/docker.rs`). `USERPROFILE` also gives the default clone root `%USERPROFILE%\Traygent` (`repo.rs`, ADR-0006). To find gh.exe, `github/discover.rs` additionally reads `ProgramW6432`, `ProgramFiles(x86)`, `ProgramData`, `SCOOP`, `SCOOP_GLOBAL` and `ChocolateyInstall`. gh runs with a minimal environment (`github/process.rs → KEPT`: profile, app data, temp, proxy and CA variables, plus `GH_CONFIG_DIR` and `XDG_CONFIG_HOME` when absolute, a relative `XDG_CONFIG_HOME` is dropped); `GH_TOKEN` / `GITHUB_TOKEN`, `GH_HOST`, `GIT_*` and askpass settings never reach it.

## Secrets Locations

Secrets are never committed. No secret is needed to build or test. The release workflow uses only the repository `GITHUB_TOKEN`; any further CI secret belongs in the CI secret store. Demo data and captures are synthetic. No `.env` file is used; a local one would stay gitignored. A new secret gets a placeholder in `.env.example` and a question to the user — never `gh secret set` unprompted. With `docker.ghToken` enabled, the session reads the connected account’s credential from the Windows vault and forwards it to the container through `-e GH_TOKEN`. The token is absent from the plan and its arguments, the host clone, `state.json` and the snapshot. Git inside the container uses the same account through the GitHub CLI credential helper. Agent logins live in the agents' own config dirs or Docker volumes, never in Traygent's files.
